Learning to explore by being unsure: PEARL, rebuilt from scratch

An agent dropped into a new task doesn't know what the task is. PEARL keeps a belief about it, acts as if one guess from that belief were true, and narrows the belief with every reward it sees. Because the belief is learned separately from the policy, it can all be trained off-policy, from old data.

The problem: adapting fast without wasting data

Meta-reinforcement learning trains on a distribution of related tasks (reach this goal, run at that speed) so that a new task from the same distribution can be solved from a handful of trajectories. Earlier methods such as MAML and RL² learned on-policy: every gradient step needed fresh data from the current policy, so meta-training cost tens of millions of environment steps.

PEARL's claim is that this cost isn't necessary. Its authors report that it is 20–100× more sample-efficient in meta-training than prior methods, and reaches higher asymptotic performance on their MuJoCo benchmarks.

reported, not reproduced These are the paper's MuJoCo numbers (arXiv 1903.08254, abstract). This project runs only cheap 2D tasks on a laptop and does not re-measure them.

The idea in one paragraph

Treat "which task am I in?" as a hidden variable z. An inference network reads a set of transitions c = {(s, a, r, s′)} and outputs a Gaussian belief q(z | c). The policy π(a | s, z) and critic Q(s, a, z) are ordinary soft actor-critic (SAC) networks that also get z. At meta-test time the agent starts from the prior, samples a z, commits to it for a whole trajectory, then updates the belief and samples again. That is posterior sampling: it explores coherently, because each trajectory tests one hypothesis.

Why is off-policy suddenly possible? The policy and critic can learn from any old data, as long as they're told the right z. Only the encoder's input, the context, needs to look like what the agent will see at test time. So PEARL samples the context from recent data and the RL batch from all data. The experiments below test that choice directly.

The maths, one piece at a time

1. Every transition casts a Gaussian vote

The encoder fφ looks at one transition cn and outputs a mean and a variance: a factor Ψφ(z | cn) = N(μn, σ²n). The posterior is the product of these factors:

qφ(z | c1:N) ∝ ∏n Ψφ(z | cn)

A product of Gaussians is again Gaussian, with a closed form: precisions add, and the mean is the precision-weighted average.

1/σ² = Σn 1/σ²n,    μ = σ² Σn μn/σ²n

Code: pearl/gaussian.py, 4 lines. A test checks it against brute-force multiplication of densities on a grid.

Three consequences follow from that formula. Order doesn't matter (the encoder is permutation-invariant, as it should be, since a set of transitions has no order). More evidence can only narrow the belief. And a transition the encoder finds uninformative can simply output a huge variance and drop out of the vote. Try it:

2. The belief is kept honest with a KL bottleneck

Without a constraint, the encoder could pack everything about the context into z, including noise that won't generalise. PEARL adds a variational information bottleneck. It penalises how far the posterior is from a standard normal prior:

LKL = β · Σtasks KL( q(z | c) ‖ N(0, I) ),   KL = ½ Σ (σ² + μ² − 1 − log σ²)

The prior also has a job at test time. It is where exploration starts, because before any data the agent samples z ~ N(0, I). With β = 0.1 (dense tasks) or 1.0 (sparse), the weights are taken from the authors' configs.

3. The encoder learns from the critic, not the policy

What should z encode? Not a reconstruction of the transitions, but whatever helps predict value. The encoder's only learning signal (besides the KL) is the critic's Bellman error, backpropagated through the reparameterised sample z = μ + σ ε:

Lcritic = E [ ( Q(s, a, z) − (r + γ V̄(s′, z̄)) )² ],   z ~ qφ(z | c)

The policy and the value network see z with gradients stopped. A unit test (test_encoder_gets_gradient_from_critic_not_policy) checks this routing, because getting it wrong fails silently: training still runs, it just doesn't meta-learn.

4. The whole training loop

for each iteration:
    for 5–10 random training tasks:
        clear that task's encoder buffer                 # context = recent data only
        collect trajectories with z ~ prior              # -> both buffers
        collect trajectories with z ~ posterior          # -> both buffers (or RL buffer only)
    repeat N times:
        pick 16 tasks; for each: context c from encoder buffer, RL batch from replay buffer
        mu, var = product_of_gaussians(encoder(c)); z = mu + sqrt(var) * eps
        critic loss + KL  -> update Q1, Q2, encoder
        value loss, policy loss (z detached), soft update of target V

This is PEARL.train and PEARL.train_step in pearl/trainer.py, line for line against the authors' rl_algorithm.py and sac.py.

Ablations: what each design choice buys

Pitfalls (or why it might not have worked last time)

  • Gradient routing. The encoder must get gradients from Q and the KL only. If it learns from the policy loss, or gets no gradient at all because z was detached everywhere, training still runs but z carries no task information.
  • Context from the wrong data. If the context comes from the whole replay buffer, it mixes old policies' behaviour with recent behaviour, and at test time the encoder sees a distribution it never trained on.
  • Reward scale. The point-robot configs use reward_scale = 100. With SAC's entropy bonus fixed at 1, the reward scale sets how deterministic the policy becomes. Too small, and the policy stays random.
  • Sparse rewards are only half sparse in the reference code. In sac.py, sample_sac notes "rewards are always dense": the critic trains on dense rewards and only the encoder sees sparse ones. This build does the same to stay faithful, and flags it here.
  • Evaluation protocol. Returns depend on how many exploration trajectories run before the posterior is used (1 for dense tasks, 5 for sparse), and on whether the policy acts deterministically (it does).

Limits

  • No MuJoCo tasks, so no direct check of the paper's headline numbers. The sparse-goal exploration result is the closest analogue, and it is checked qualitatively.
  • Short training (the run-budget table) and narrower networks (128 units instead of 300). Absolute returns may sit below what full-length training would reach.
  • 3 seeds give a rough spread, not a confidence interval.
